# 明鉴 · 个股证据诊断

> 输入一只 A 股，输出一份标注了「**事实 / 推断 / 未知**」与「**正面 / 负面 / 中性 / 矛盾**」的证据地图。
> 每一条结论都能点回原始字段。
> **它不告诉你该不该买，它告诉你能确定什么、在推断什么、以及还有什么你不知道。**

---

## 1. 它解决什么问题

个人投资者面对一只股票时，真正的困难往往不是"没有信息"，而是**分不清手里这些信息哪一条是事实、哪一条是别人的猜测、哪一条其实根本查不到**。

现有工具的两个极端都不解决问题：

- **太浅**：看一眼 K 线和涨跌幅，得到的印象没有依据；
- **太深**：机构终端功能强大，但对个人投资者门槛过高。

更麻烦的是第三点：AI 生成的分析往往**语气笃定却没有依据**，用户无从核实。

明鉴只做一件事：**把证据摆开、标清楚它是哪一类、并且允许用户一路点回原始数据。**

## 2. 目标用户与产品定位

**用户**：有投资经验、希望自己做判断、但不信任荐股的自主决策型个人投资者。

**定位**：与同花顺「问财」互补而非竞争 —— 问财给"答案"，明鉴给"证据与判断框架"。

**我们刻意不做的事**：

| 不做 | 原因 |
|---|---|
| 输出"好 / 坏"标签 | 这是替用户下判断 |
| 涨跌预测、收益承诺、买卖建议 | 合规红线 |
| 数据缺失时补零或估算 | **静默生成"正常"结论是最严重的错误** |

## 3. 核心：双坐标证据模型

一条证据不是"一个类型"，而是**两个独立坐标**（详见 `diagnose.py`）：

| 坐标 | 取值 | 编码方式 | 回答 |
|---|---|---|---|
| **认知** | 事实 / 推断 / 未知 | 卡片左侧**线型** | 这条我们是怎么知道的？ |
| **倾向** | 正面 / 负面 / 中性 / 矛盾 | 标签**颜色** | 这条指向哪个方向？ |

未知项**没有倾向**——不知道的东西不能有方向。

### 为什么有「中性」

题目列了正面/负面/矛盾/未知四类。本项目加了第五类「中性」，理由是：

> **一条孤立的数字本身不含方向。** "营业收入同比 +6.36%"——增长是正号，但增速已从 19% 掉到 6%，你说它是正面还是负面？

强行把每个数字塞进"正面/负面"就是替用户下判断。所以单期数值标为**中性**，方向交给**同口径趋势序列**去表达。

### 倾向必须带规则

"正面/负面"不是观点，是**规则判定**。每条倾向都携带规则编号，点开即可查看：

| 规则 | 内容 |
|---|---|
| L-00 | 单期数值不含方向 → 中性 |
| L-01 | 同一指标在同口径报告期上连续单调下降 → 负面（上升 → 正面） |
| L-02 | 同报告期利润增速 > 0 且净利现金含量 < 100% → 矛盾 |
| L-03 | 连续三期极差 < 1 个百分点 → 正面（稳定性） |
| L-04 | 加权 ROE 与 15% / 8% 阈值比较 |
| L-05 | 净利率 > 20% 且资产负债率 < 40% → 正面 |
| L-06 | 同标的两口径估值比值 > 3 → 矛盾 |
| L-07 | 单期同比为负 → 负面 |
| L-10 | 推断的倾向继承其所引用事实的多数方向 |

### 口径纪律

同比增速**只在同类型报告期之间比较**（年报比年报、中报比中报）。

把年报、三季报、一季报混进一根趋势序列是错误做法 —— 报告期长度不同，不可比。本项目在开发过程中真实犯过这个错，见 [VALIDATION.md](VALIDATION.md) 缺陷 #3。

## 4. 三层分工：谁算什么

```
① 数据接入      扶摇 REST API
                          │
② 确定性计算     纯代码：取数、摊平指标、算趋势、跑规则              ← 数字归代码
                          │  事实 / 未知 / 矛盾 在这里判定
③ 证据装配       统一 evidence 对象（含来源四要素：接口/时点/单位/口径）
                          │
④ 推断解读       模型，只接收「事实」，输出必须引用事实编号，
                 引用不存在 → 整条丢弃                       ← 语言归模型
                          │
⑤ 前端           构成条 + 证据卡片 + 三层钻取
```

**关键立场**：风险最高的三类证据（事实、未知、矛盾）**完全不需要模型**，全部由确定性代码产出。模型只被允许在最小范围内说一句话，而且必须可核对。

## 5. 快速开始

**环境要求**：Python 3.8+。**不需要安装任何第三方库**，全部使用标准库。

```bash
cd 项目目录
python app.py
```

然后打开 <http://127.0.0.1:8765/>

页面顶部可以修改股票代码与同业列表，点击「诊断」会**实时调用扶摇接口**。

也可以直接用命令行产出 JSON：

```bash
python diagnose.py 600519.SH --peers 000858.SZ,000568.SZ,002304.SZ --out out/600519.json
```

## 6. 密钥与安全

### 密钥放在哪里

**项目目录里不放任何真实密钥。** 全部放在用户目录：

```
~/.hithink-finance/credentials.env
```

Windows 即 `C:\Users\<你的用户名>\.hithink-finance\credentials.env`，内容：

```
HITHINK_FINANCE_API_KEY=你的扶摇key
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_MODEL=glm-4.7-flash
LLM_API_KEY=你的模型key
```

程序按「**环境变量优先 → 用户级凭据文件**」的顺序读取。

**为什么要这样设计**：`.gitignore` 只挡得住 `git add .` 这一条路，它挡不住 `git add -f`、挡不住把文件夹压成 zip 上传、挡不住手动拖拽。**只要密钥不在项目目录里，任何打包方式都带不走它。**

### 推送或打包前的自检

```bash
python check_secrets.py
```

它用真实密钥的值去扫项目目录里的每一个文本文件，并检查：项目内有没有凭据类文件、git 是否已经跟踪了敏感文件。**退出码非 0 就不要打包、不要推送。**

### 环境变量

部署时也可以直接用环境变量，变量名如下：

| 变量 | 必填 | 说明 |
|---|---|---|
| `HITHINK_FINANCE_API_KEY` | 是 | 扶摇 API Key，[申请地址](https://fuyao.aicubes.cn/admin/) |
| `LLM_BASE_URL` | 否 | 推断层的 OpenAI 兼容端点。**不填则推断层不启用** |
| `LLM_API_KEY` | 否 | 推断层 Key |
| `LLM_MODEL` | 否 | 模型名，例如 `glm-4.7-flash` |

常见国内模型配置：

```
智谱 GLM   LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4              LLM_MODEL=glm-4-flash-250414
DeepSeek   LLM_BASE_URL=https://api.deepseek.com/v1                       LLM_MODEL=deepseek-chat
通义千问   LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1 LLM_MODEL=qwen-turbo
硅基流动   LLM_BASE_URL=https://api.siliconflow.cn/v1                     LLM_MODEL=Qwen/Qwen3-8B
```

> ⚠️ **模型名踩坑记录**：智谱当前的"新 Flash" `glm-4.7-flash` 是**推理模型**，
> 实测回复两个字要 **57 秒**，本场景不可用。请用 `glm-4-flash-250414`，
> 同样的请求只要 **0.4 秒**。详见 [VALIDATION.md](VALIDATION.md) 缺陷 #11。

配置好后先自检，再启动：

```bash
python llm.py     # 自检推断层，会打印接受 / 丢弃明细
python app.py     # 启动产品
```

**不配置推断层也能完整运行**：事实、未知、矛盾三类证据由代码产出，不受影响；页面会把"推断层未启用"如实标注为一条未知证据，而不是报错或沉默。

## 8. 数据来源

数据全部来自**同花顺金融数据服务（扶摇）**，Base URL `https://fuyao.aicubes.cn`，认证方式为 HTTP Header `X-api-key`。

| 维度 | 接口 | 说明 |
|---|---|---|
| 标的消歧 | `GET /api/meta/tickers/search` | 名称 / 代码消歧 |
| 财务趋势、经营质量 | `GET /api/a-share/financials/indicators` | 单只标的、单个报告期的五类能力块指标 |
| 估值 | `GET /api/a-share/valuations/snapshot` | 批量，单次最多 100 个标的 |
| 行情特征 | `GET /api/a-share/prices/snapshot` | 快照，含开高低收与前收 |
| 重要事件与风险 | `GET /api/news/events/search` | **端内专用，公开接口不可达**（见下） |

**响应信封**：`{code, message, request_id, data}`。本项目的取数层把 `request_id`、`retrieved_at`、`code`、`message` 全部保留在证据的 `source` 字段里，构成可追溯链。

**多期趋势的追溯**：一条跨三个报告期的趋势证据，其 `source.contributions` 会逐条列出每个报告期的取值与各自的 `request_id`。

## 9. AI 的角色

| 环节 | 谁做 | 说明 |
|---|---|---|
| 取数、指标计算、趋势判定 | **代码** | 模型不参与任何算术 |
| 事实 / 未知 / 矛盾 的判定 | **代码** | 规则判定，附规则编号 |
| 正面 / 负面 的判定 | **代码（规则）** | 不是模型自评 |
| 文字解读（"推断"） | **模型** | 只能看事实，必须引用事实编号 |
| 引用校验 | **代码** | 引用不存在的证据 → 整条丢弃 |

**模型被明确禁止**：引入事实清单以外的知识、预测涨跌、给出买卖建议、给事实自评方向。

推断层在无 Key 时不启用，且这一状态**如实展示**给用户。

## 10. 已知边界

这些是**能力边界**，不是 bug。产品在界面上明确标注它们，而不是假装不存在。

| # | 边界 | 原因 |
|---|---|---|
| 1 | **重大事件与风险拿不到** | 扶摇资讯接口为同花顺 AI 客户端专用，公开 API 返回 `code=2004`。目前作为"待验证问题"列出 |
| 2 | **没有历史估值分位** | 估值接口明确不提供历史序列，只能做当期 + 同业横向对比 |
| 3 | **同业列表需手工提供** | 未接入板块成分股接口，同业由使用者填入 |
| 4 | **推断层默认不启用** | 未配置 Key 时；事实/未知/矛盾不受影响 |
| 5 | **报告期披露有时滞** | 未披露的报告期返回业务码，被如实记为"未知"，不补零 |
| 6 | **单次诊断约 10–30 秒** | 需要拉取 12 个报告期，逐期请求 |

## 11. 未做事项

诚实列出没有做的事：

1. **未部署公网 URL** —— 当前为本地运行
2. **未做"根据用户问题选择维度"** —— 页面上的问题选项目前是静态展示，不驱动维度切换
3. **未区分公司类型** —— 银行、券商与消费股的指标口径不同，当前所有标的套用同一套指标
4. **行情特征维度偏薄** —— 目前只有一条当日快照证据，未做区间涨跌幅、波动率、成交特征
5. **行业位置维度未做实** —— 只有估值横向对比，没有板块归属、行业排名
6. **极端输入未做全面校验** —— 非法代码会走到接口层由业务码兜底，但未做前置校验
7. **未做缓存** —— 每次诊断都重新取数

## 12. 不做什么（红线）

- 不输出确定性涨跌预测
- 不输出收益承诺
- 不输出直接买卖建议
- 不在数据缺失、冲突、过期或调用失败时静默生成"正常"结论
- 不在仓库中提交 API Key
